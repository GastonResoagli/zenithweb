============================================================================
 CONFIGURACIÓN DE VARIABLES DE ENTORNO — ZenithWeb
============================================================================
 Sistema de Gestión de Stock de Paneles Solares.
 Hay DOS proyectos con sus propias variables: el BACKEND (Express) y el
 FRONTEND (Vite/React). Cada uno usa un archivo .env propio.

 IMPORTANTE: los archivos .env NO se suben al repositorio (están en .gitignore).
 Solo se versionan los .env.example como plantilla.

============================================================================
 1) BACKEND — archivo:  .env   (en la raíz del proyecto)
============================================================================

 -- DESARROLLO LOCAL (PostgreSQL en tu máquina) --

   DB_USER=postgres                # usuario de PostgreSQL
   DB_HOST=localhost               # host de la base
   DB_NAME=control_stock           # nombre de la base de datos
   DB_PASSWORD=5252                # contraseña del usuario de PostgreSQL
   DB_PORT=5432                    # puerto de PostgreSQL (default 5432)

   JWT_SECRET=<secreto largo y aleatorio>   # firma de los tokens JWT (OBLIGATORIO)
   PORT=3000                       # puerto donde corre el backend

 -- PRODUCCIÓN (Render + Supabase) --
   En vez de las DB_* se usa una sola connection string. Si DATABASE_URL está
   definida, el backend la usa con SSL e IGNORA todas las DB_* de arriba.

   DATABASE_URL=postgresql://postgres.<ref>:<password>@<host>:6543/postgres
   FRONTEND_URL=https://zenithweb.vercel.app   # restringe el CORS al front
   JWT_SECRET=<el mismo tipo de secreto>
   # PORT lo inyecta Render automáticamente.

 -- Cómo generar un JWT_SECRET seguro --
   Ejecutar en una terminal (con Node instalado):
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   Copiar el valor resultante en JWT_SECRET.

 NOTA: si se cambia el JWT_SECRET, todos los tokens emitidos antes quedan
 inválidos -> hay que volver a iniciar sesión. Es el comportamiento esperado.

============================================================================
 2) FRONTEND — archivo:  client/.env
============================================================================
 Las variables expuestas al navegador DEBEN empezar con VITE_.

 -- DESARROLLO LOCAL --
   VITE_API_URL=http://localhost:3000     # URL del backend local

 -- PRODUCCIÓN (Vercel) --
   VITE_API_URL=https://zenithweb-api.onrender.com   # URL del backend en Render
   (sin barra final). Se configura en Vercel > Settings > Environment Variables.

 Si VITE_API_URL no se define, el front cae por defecto a http://localhost:3000.

============================================================================
 3) PUESTA EN MARCHA RÁPIDA (local)
============================================================================
 1. Copiar .env.example  ->  .env           (raíz, backend)
 2. Copiar client/.env.example  ->  client/.env   (frontend)
 3. Completar los valores según las secciones de arriba.
 4. Generar y pegar un JWT_SECRET (ver comando más arriba).
 5. Backend:   npm start         (queda en http://localhost:3000)
 6. Frontend:  cd client && npm run dev

============================================================================
 4) RESUMEN: dónde lee cada variable el código
============================================================================
   DB_USER/HOST/NAME/PASSWORD/PORT ... src/db/connection.js  (modo local)
   DATABASE_URL ...................... src/db/connection.js  (modo producción)
   JWT_SECRET ....................... src/services/authService.js (firma)
                                       src/middleware/authMiddleware.js (verifica)
   PORT ............................. index.js
   FRONTEND_URL ..................... index.js  (CORS)
   VITE_API_URL ..................... client/src/api/*.js
============================================================================
